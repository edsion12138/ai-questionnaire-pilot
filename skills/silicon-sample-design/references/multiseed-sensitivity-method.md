# 多种子×多测量情景的硅样本稳定性与量表迭代（v1.1）

## 适用目的

在初步构念和候选题项已经通过文献审查、专家审核、认知访谈之后，用**固定生成机制下的重复模拟**识别测量结构对随机响应误差、较低共同性、交叉载荷以及题项删减的敏感性。本流程不是“选择一批统计指标最漂亮的假受访者”，更不能据此将模拟数据描述为真人回收。

> **12＋2＋2原则**：固定12个不同种子的中等测量清晰度情景，另外分别固定2个较高噪声和2个较高共同性情景。种子、测量参数、候选删题方案、分析规则须在看到本轮分析结果之前冻结。16轮是敏感性实验的设计，不是一个普遍最优数量，也不提供16项独立实证研究的意义。

## 1. 开始前：构念图与题项蓝图

先把问卷分为：核心能力（被解释构念）、背景事实（单题或多选）、环境支持/心理与行为前因（解释构念）、独立效标、开放题。审查同一语义是否跨核心与前因出现，识别双重行为、跨专业含义不一致、覆盖不足。

形成一张“维度—定义—核心行为—题项—唯一内容价值”映射表。构念属性错置时优先**移出或重新归属**，而不是通过强行合并/删题掩盖理论问题。例如“学习与适应”更符合本研究的学习前因，而软硬件操作强调直接使用工具本身，不包括利用工具产生方案、模型和分析结论。

## 2. 固定情景设计

| 情景 | 次数 | 变动维度 | 核心任务 |
|---|---:|---|---|
| 中等测量清晰度 medium | 12 | 固定参数；仅更换独立种子 | 判断波动范围、达标频率、弱题是否重复暴露 |
| 较高噪声 noise | 2 | 相比medium降低预设主载荷、适度增大交叉/方法影响 | 检查结构压力下是否退化 |
| 较高共同性 high | 2 | 相比medium提高主载荷、适度降低交叉/方法影响 | 观察乐观上界，识别结果是否只在理想条件下出现 |

中等清晰度、噪声与较高共同性是**模拟机制的参数命名**，不是大语言模型识别出的人群属性。建议对每个题项固定一个独立参数，**跨种子不重新调参**。各轮只有随机响应实现不同。

### 建议的增强：8＋4的种子保留机制

原有12种子迭代可完整呈现12/12稳定性。为防止同一批中等情景既用于确定题项、又宣称独立证实最优，v1.1进一步推荐：先用8个中等种子开发候选，再将剩余4个中等种子作为**未参与删题筛选的seed holdout**；最后检查4个高/低压力种子。该保留机制检验的是不同模拟实现，**仍不是真实样本独立验证**。同一种子内部再按专业×年级等背景分层，固定拆分探索组与验证组（如443/443）。

## 3. 分析样本与双层防泄漏

1. 数据筛查（问卷的真实性、注意力检查、未接触选项、缺失分布）先于质量指标分析；模拟发放与有效筛查须另立审计表，不能把虚构的“发放量”表述为现场调查。
2. 在量表**原始题库**上确定完整案例，后续删题比较沿用相同受访者集合：避免“删除一题后可用样本数增加”造成不公平比较。
3. 对每个独立随机种子，先固定背景分层和探索组/验证组标签。探索组用于项目诊断、平行分析和EFA；验证组用于预设模型CFA、CR/AVE及区分效度。
4. 在探索组选择项目，再于该轮验证组复核，仍需注意跨种子重复调参会产生选择偏差；8个开发种子之外的4个seed holdout用于最终对照，结果不得再用于回头改写候选。
5. 如有数智胜任力、影响因素和效标三个模块，**分别**对各潜变量块做EFA和CFA，效标单独计分；若核心与影响因素在同一份作答中采集，可进一步做联合多因子CFA和跨块HTMT检验，但不得用独立生成的数据拼接成同源数据。

## 4. 标准十步检验与多情景汇总

数据准备完成后，报告：**描述性统计 → CMB → 项目分析 → KMO/Bartlett与平行分析 → EFA → CFA → 信度α/ω/CR → 聚合效度/AVE → 区分效度Fornell–Larcker与HTMT → 效标关联效度。**

每项按「每轮明细」「12种子中位数」「最小—最大或10—90百分位」「12轮达标次数」「噪声2轮」「高共同性2轮」「8开发/4留出」展示；不要仅呈现平均值或表现最好的一轮。区分：

- **新脚本实际计算范围**：α、KMO、平行分析、PAF+Oblimin EFA载荷/交叉载荷及HTMT；KMO、平行分析和EFA使用探索组，α与HTMT使用验证组。脚本不计算ω、CITC或Bartlett检验。情景与分组参数见`frozen_design.json`和`manifest.json`。
- **CFA/CR/CFA-AVE/Fornell–Larcker、单因子CFA/CMB、效标关联**：当前新脚本**不提供**；必须在正式psychometric-pretest流程中按量表数据类型和模型估计器完成，不能把EFA载荷平方或模拟设定载荷误称为验证性AVE。
- Harman首因子解释率只是辅助筛查；真正同源数据中的方法效应仍可能存在。
- 若1—5 Likert用相关矩阵正态ML，应注明近似估计；正式真人数据优先考虑多分相关、WLSMV/DWLS或稳健估计。

## 5. 题项方案比较，不是指标竞赛

每个候选版本应同时记录：①理论与构念边界；②删题之前预设的统计风险；③多种子指标变化；④内容覆盖与独特侧面损失；⑤跨专业群体的作答适用性；⑥问卷长度；⑦最终人工决定。

默认候选操作：**保留／观察／改写／候选删除／转移至其他构念**。不应因为模拟AVE低于0.50就直接删除有独特内容价值的题项。构念合并、拆分或移除须有理论依据，而非仅看模拟因子数。

## 6. 真实实例：职业本科数智胜任力量表

本研究经历了45题9维初始版、35题精简版、再次扩充与认知访谈审查、最终重新划分核心/影响因素边界，最后形成39题8维核心、32题9构念影响因素、10题DigComp效标的候选问卷。重要策略如下：

- **构念层先于题项层**：原“学习与适应”不适合继续作为数智胜任力核心维度，整体移出核心模块并将有关内容安置到前因变量，避免能力和学习行为混测。
- **职业性与可迁移性同时保障**：原软硬件操作题充分聚焦设备/软件的直接操作，信息与数据管理独立出来；“借助工具形成方案或分析结果”按产出功能进入相关维度。
- **内容重构而非机械剔除**：将原“开发与实施”中混杂的任务执行和开发内容重构为“数字内容生产”；根据认知访谈减少抽象词语。
- **删题策略可因新模拟而反转**：某轮D2_06曾被认为可精简，但后续12种子模拟发现其表现良好；反而D2_01、D2_02的精简在预设情景中较稳定。这说明不能直接迁移某个随机情景下的“最佳删题名单”。
- **有价值的内容宁可保留**：D7“运行监测与故障诊断”的异常识别、风险评估、故障排查、趋势监测、恢复确认构成完整工作链，既有统计指标已较好时，不应为进一步提升AVE删去核心环节。
- **最终39题是候选，而不是已通过真实预测试的成品**：删除操作维度两题和数字内容加工/转换题之后，在较高共同性模拟中可达到理想指标，但这同样是生成条件决定的模型演练结果。

## 7. 停止迭代的规则

同时满足以下条件时应停止围绕硅样本反复调优，转入真人预测试：理论结构已可解释、主要题文经认知访谈可理解、跨专业内容基本覆盖、重复题有所压缩、指标在中等情景的分布可接受、压力情景中的问题已记录并拟定真实测试重点。若高共同性情景全部达标而噪声情景持续失败，要将其记录为**参数敏感性**，不能继续抬高载荷直到每轮通过。

## 8. 必须留档的产物

- 版本图谱、跨版题号映射、每项修改理由、删题内容代价；
- 完整硅样本及人设/背景生成规则、种子列表、情景参数、分析代码及软件版本；
- 按同一完整案例的每轮样本保留数、分层拆分、EFA/CFA结果；
- 12种子稳定性表与2＋2情景压力表、失败情景、未通过指标；
- 人类研究者决策表与后续真人预测试需要补证的分析步骤。

**可复现命令：**

```bash
python skills/silicon-sample-design/scripts/multiseed_sensitivity.py \
  skills/silicon-sample-design/assets/example-multi-scenario-config.json \
  --out sensitivity_output --save-raw
```

输出`frozen_design.json`（设计快照）、`manifest.json`（16轮生成参数及分层规则）、`runs.json`、`runs_flat.csv`、`summary.json`（8开发/4留出＋压力情景汇总）、`samples/*.csv`（选用 `--save-raw` 时）。

### 与LLM-persona模式的界线

本参考脚本是**参数式、离散化潜变量响应生成器**，用于校准和压力测试分析流程；不是调用LLM逐个扮演受访者的代码。若研究者另行通过LLM API构建persona作答，必须保留模型名称与版本、提示词、persona配置、温度及批次参数、原始输出，且不得将真实/LLM/参数式三种数据来源混称或混合宣称实证效度。
